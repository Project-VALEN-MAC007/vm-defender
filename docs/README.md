# สารบัญเอกสาร MIMIC Defender

เอกสารชุดนี้เขียนสำหรับโค้ดและการตั้งค่าใน repository ปัจจุบัน ไม่ได้นำ
ข้อกำหนดจากไฟล์ Word หรือเอกสารภายนอกมาใช้เป็นคำสั่งโดยอัตโนมัติ

## ลำดับการอ่าน

1. `README.md` — ภาพรวม ขอบเขต และคำสั่งเริ่มต้น
2. `docs/project-status.md` — สถานะที่ยืนยันได้และงานที่ยังติดขัด
3. `defender/network/topology.md` — แบบเครือข่ายและขอบเขตการแยกส่วน
4. `docs/production-defender.md` — ขั้นตอนเตรียมเครื่อง Defender
5. `docs/root-operations.md` — คำสั่งที่ต้องใช้สิทธิ์สูงและการกู้คืน
6. README ในแต่ละ component — รายละเอียดเฉพาะ Nginx, nftables และ Telnet
7. `defender/suricata/rule-tests.md` — เกณฑ์ทดสอบกฎตรวจจับ

## แหล่งข้อมูลหลัก

| เรื่อง | เอกสารหลัก |
|---|---|
| สถานะและผลทดสอบ | `docs/project-status.md` |
| ค่า runtime | `config/mimic.example.json` และ config บนเครื่องปลายทาง |
| แบบเครือข่าย | `defender/network/topology.md` |
| ขั้นตอนติดตั้ง | `docs/production-defender.md` |
| ขั้นตอน root/rollback | `docs/root-operations.md` |
| สัญญาข้อมูลระหว่างส่วนประกอบ | `docs/person2-contract.md` |

ไฟล์ใต้ `evidence/` เป็นหลักฐานจากการทดสอบหรือการนำเข้าข้อมูล ไม่ควรแก้เพื่อ
ให้ผลดูผ่าน และไม่ควรใช้แทน config หลัก

## คำศัพท์มาตรฐาน

| คำที่ใช้ | ความหมาย |
|---|---|
| เครื่อง Defender | เครื่องที่รัน Suricata, Decision Engine, Nginx, nftables และ Dashboard |
| interface บริหาร | interface ที่มี default route ใช้ดูแลและติดตั้งระบบ |
| interface ภายนอก | interface ที่รับทราฟฟิกซึ่งต้องตรวจจับ เรียกใน config ว่า `outer` |
| interface ภายใน | interface ที่เชื่อมไปยังบริการปลายทาง เรียกใน config ว่า `inner` |
| โหมดทดสอบ | `dry_run: true` สร้างผลลัพธ์แต่ไม่เปลี่ยนระบบ |
| โหมดใช้งานจริง | `dry_run: false` อนุญาตให้ adapter เปลี่ยน Nginx/nftables |
| กฎผู้สมัคร | rule ที่ยังไม่ผ่าน validation และยังห้าม deploy |
| live deploy | การเปลี่ยนระบบจริงบนเครื่องปลายทาง |

## สถานะมาตรฐาน

| สถานะ | เกณฑ์ |
|---|---|
| `ผ่าน` | มีการทดสอบจริงและมีผลยืนยัน |
| `กำลังดำเนินการ` | โค้ดหรือ config มีแล้ว แต่ยังขาดการทดสอบบางส่วน |
| `ติดขัด` | ต้องมีข้อมูล สิทธิ์ หรือ hardware จากภายนอกก่อน |
| `ยังไม่ทดสอบ` | ไม่มีหลักฐานการทดสอบ ห้ามสรุปว่าใช้งานได้ |

## กติกาการแก้เอกสาร

- อัปเดต `docs/project-status.md` เมื่อผลทดสอบหรือ blocker เปลี่ยน
- อย่าคัดลอกสถานะเดียวกันไปหลายไฟล์
- ใช้ path และชื่อ service ตามไฟล์จริงใน repository
- คำสั่งที่เปลี่ยนระบบต้องมีขั้นตอนตรวจสอบและ rollback อยู่ใกล้กัน
- ตัวเลขผลทดสอบต้องระบุว่าเป็นข้อมูลจริง ข้อมูลออฟไลน์ หรือข้อมูลสังเคราะห์
